# Ажурирања {#updates}

3DHeat CS2 сам се одржува ажурен од [изданијата на GitHub](https://github.com/Holdi601/3DHeat-CS2/releases)
на ова складиште. Код:
[`heat3d_update/__init__.py`](https://github.com/Holdi601/3DHeat-CS2/blob/main/heat3d_update/__init__.py),
[`heat3d_update/__main__.py`](https://github.com/Holdi601/3DHeat-CS2/blob/main/heat3d_update/__main__.py).

## Проверката при стартување {#the-check-at-start-up}

Секој `python -m heat3d_cs2 ...` најпрво прашува дали има ново издание, уште
пред да ги прочита своите аргументи:

1. Инсталираната верзија е датотеката `VERSION` во коренот на складиштето
   (`0` ако не може да се прочита).
2. Најновото издание се бара од
   `https://api.github.com/repos/Holdi601/3DHeat-CS2/releases/latest`, со
   тајмаут од **5 секунди**. Одговорот се кешира **6 часа** во
   `%LOCALAPPDATA%\3DHeat\update-check-3DHeat-CS2.json` (на системи без
   `LOCALAPPDATA`: `~/.cache/3DHeat/update-check-3DHeat-CS2.json`), па барањето
   се праќа најмногу на секои шест часа. „Сè уште ништо не е објавено“ (HTTP
   404) се кешира како одговор. Без интернет, со ограничување на барања, зад
   прокси - секоја друга грешка - алатката продолжува со верзијата што ја има,
   и ништо не се кешира.
3. Верзиите се споредуваат како броеви: `v1.2.3` и `1.2.3` се еднакви, сè
   по `-` или `+` се игнорира, деловите што недостигаат се бројат како 0.

Кога има ново издание, го кажува тоа на потокот за грешки:

```text
[heat3d_cs2] 3DHeat CS2 1.1.0 is out (this is 1.0.1). https://github.com/Holdi601/3DHeat-CS2/releases/tag/v1.1.0
Update now? [Y/n]
```

- На терминал (и влезот и потокот за грешки се терминали) прашува. Enter,
  `y`, `yes`, `j` или `ja` ажурира; сè друго продолжува непроменето. По
  ажурирањето **истата команда се извршува повторно**, на новиот код.
- Без терминал - закажано извршување, pipe - само печати каде да се ажурира и
  продолжува: `Run python -m heat3d_update in <folder> to update.`

`HEAT3D_NO_UPDATE=1` ја исклучува проверката. Секоја вредност освен празна,
`0`, `false` или `no` се смета за вклучена.

## Ажурирање на барање {#updating-on-request}

```bash
python -m heat3d_update            # update to the newest release
python -m heat3d_update --check    # only say whether one is out
```

Ова секогаш го прашува GitHub (кешот не се користи). Печати `Up to date: <version>.`,
`No release found (this is <version>); offline, or nothing published yet.`, или
`<new> is out (this is <current>): <url>` и потоа ажурира (освен со `--check`).
Излезен код `1` кога ажурирањето е обидено и не успеало, инаку `0`.

## Како се применува ажурирањето {#how-an-update-is-applied}

Зависи од тоа како е инсталирана копијата:

- **Git checkout** (има `.git` во коренот и `git` на `PATH`):
  `git pull --ff-only`. Се одбива додека следените датотеки имаат локални
  промени („this checkout has local changes; commit or stash them, then run
  `git pull`“): тоа е нечија работа, а ажурирањето не одлучува што ќе се
  случи со неа. Неследените датотеки не го блокираат.
- **Преземена копија**: изворната архива на изданието (zipball на GitHub) се
  презема и се распакува во привремена папка - записите што би слетале надвор
  од неа се прескокнуваат - а нејзиниот `VERSION` мора да е верзијата што
  изданието ја тврди, инаку ништо не се менува („the archive is version X, not
  Y“). Потоа нејзините датотеки се копираат врз папката. Датотеките што не се
  дел од изданието - вашите демоа, излези, виртуелна околина, сè што сте
  направиле - никогаш не се допираат. Модулите на Python што изданието веќе ги
  нема се бришат од сопствените пакети на алатката (папките `heat3d_*`), па
  застарен модул не може да ја засени својата замена.

Ако ажурирањето не успее, пораката се печати и алатката продолжува со
верзијата што ја има.

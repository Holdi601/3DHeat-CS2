# Ενημερώσεις {#updates}

Το 3DHeat CS2 κρατιέται ενημερωμένο από τις [εκδόσεις του GitHub](https://github.com/Holdi601/3DHeat-CS2/releases) αυτού
του αποθετηρίου. Κώδικας:
[`heat3d_update/__init__.py`](https://github.com/Holdi601/3DHeat-CS2/blob/main/heat3d_update/__init__.py),
[`heat3d_update/__main__.py`](https://github.com/Holdi601/3DHeat-CS2/blob/main/heat3d_update/__main__.py).

## Ο έλεγχος κατά την εκκίνηση {#the-check-at-start-up}

Κάθε `python -m heat3d_cs2 ...` ρωτά πρώτα αν έχει βγει νεότερη έκδοση, πριν καν διαβάσει τα ορίσματά του:

1. Η εγκατεστημένη έκδοση είναι το αρχείο `VERSION` στη ρίζα του αποθετηρίου (`0` αν δεν μπορεί να διαβαστεί).
2. Η νεότερη έκδοση ζητείται από το
   `https://api.github.com/repos/Holdi601/3DHeat-CS2/releases/latest`, με **χρονικό όριο 5 δευτερολέπτων**. Η απάντηση
   αποθηκεύεται για **6 ώρες** στο `%LOCALAPPDATA%\3DHeat\update-check-3DHeat-CS2.json` (σε συστήματα χωρίς
   `LOCALAPPDATA`: `~/.cache/3DHeat/update-check-3DHeat-CS2.json`), οπότε το αίτημα γίνεται το πολύ κάθε έξι ώρες.
   Το «δεν έχει κυκλοφορήσει τίποτα ακόμα» (HTTP 404) αποθηκεύεται όπως μια απάντηση. Χωρίς σύνδεση, με όριο αιτημάτων,
   πίσω από διαμεσολαβητή - οποιοδήποτε άλλο σφάλμα - το εργαλείο συνεχίζει με την έκδοση που έχει, και δεν αποθηκεύεται
   τίποτα.
3. Οι εκδόσεις συγκρίνονται ως αριθμοί: το `v1.2.3` και το `1.2.3` είναι ίδια, ό,τι ακολουθεί ένα `-` ή `+` αγνοείται,
   και τα μέρη που λείπουν μετράνε ως 0.

Όταν έχει βγει νεότερη έκδοση, το λέει στη ροή σφαλμάτων:

```text
[heat3d_cs2] 3DHeat CS2 1.1.0 is out (this is 1.0.1). https://github.com/Holdi601/3DHeat-CS2/releases/tag/v1.1.0
Update now? [Y/n]
```

- Σε τερματικό (όταν και η είσοδος και η ροή σφαλμάτων είναι τερματικό) ρωτά. Enter, `y`, `yes`, `j` ή `ja` ενημερώνει·
  οτιδήποτε άλλο συνεχίζει ως έχει. Μετά από ενημέρωση, **η ίδια εντολή τρέχει ξανά**, με τον νέο κώδικα.
- Χωρίς τερματικό - προγραμματισμένη εκτέλεση, σωλήνας - απλώς τυπώνει πού να ενημερώσετε και συνεχίζει:
  `Run python -m heat3d_update in <folder> to update.`

Το `HEAT3D_NO_UPDATE=1` απενεργοποιεί τον έλεγχο. Κάθε τιμή εκτός από κενή, `0`, `false` ή `no` θεωρείται ενεργοποίηση.

## Ενημέρωση κατόπιν αιτήματος {#updating-on-request}

```bash
python -m heat3d_update            # update to the newest release
python -m heat3d_update --check    # only say whether one is out
```

Αυτό ρωτά πάντα το GitHub (η αποθήκευση δεν χρησιμοποιείται). Τυπώνει `Up to date: <version>.`,
`No release found (this is <version>); offline, or nothing published yet.`, ή
`<new> is out (this is <current>): <url>` και μετά ενημερώνει (εκτός αν είναι `--check`). Κωδικός εξόδου `1` όταν έγινε
προσπάθεια ενημέρωσης και απέτυχε, αλλιώς `0`.

## Πώς εφαρμόζεται μια ενημέρωση {#how-an-update-is-applied}

Εξαρτάται από τον τρόπο εγκατάστασης του αντιγράφου:

- **Αντίγραφο git** (υπάρχει `.git` στη ρίζα και το `git` στο `PATH`): `git pull --ff-only`. Αρνείται όταν τα
  παρακολουθούμενα αρχεία έχουν τοπικές αλλαγές ("this checkout has local changes; commit or stash them, then run
  `git pull`"): είναι δουλειά κάποιου, και μια ενημέρωση δεν αποφασίζει τι γίνεται με αυτά. Τα μη παρακολουθούμενα αρχεία
  δεν εμποδίζουν.
- **Ένα ληφθέν αντίγραφο**: το αρχείο πηγαίου κώδικα της έκδοσης (το zipball του GitHub) κατεβαίνει και
  αποσυμπιέζεται σε προσωρινό φάκελο - καταχωρίσεις που θα έβγαιναν έξω από αυτόν παρακάμπτονται - και το `VERSION` του
  πρέπει να είναι η έκδοση που δηλώνει η έκδοση, αλλιώς δεν αλλάζει τίποτα ("the archive is version X, not Y"). Μετά τα
  αρχεία της αντιγράφονται πάνω στον φάκελο. Τα αρχεία που δεν ανήκουν στην έκδοση - τα demo σας, οι έξοδοι, το
  εικονικό περιβάλλον, οτιδήποτε φτιάξατε - δεν πειράζονται ποτέ. Τα αρχεία Python που δεν υπάρχουν πια στην έκδοση
  διαγράφονται από τα πακέτα του εργαλείου (οι φάκελοι `heat3d_*`), ώστε μια παλιά μονάδα να μη σκιάσει την αντικαταστάτριά της.

Αν μια ενημέρωση αποτύχει, τυπώνεται το μήνυμα και το εργαλείο τρέχει με την έκδοση που έχει.
